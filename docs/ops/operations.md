## 日常运行

- 显示 API 和 Worker 健康、数据库可用性、每店铺最近一次成功同步、待处理错误、队列积压。
- 设置重试上限与告警：大量 401/403 授权失败、429 限流、连续任务失败、财务差异、库存数据过期。
- 同步日志只保留可定位错误的元数据，绝不记录 Token 或买家地址。
- 外部服务波动期间尽量保留可用的历史数据，UI 明确提示更新时间而非假装实时。

## 备份恢复

1. PostgreSQL 版本化备份，加密并隔离存放。
2. 恢复到独立环境，验证 schema、订单/财务记录数、关键业务查询。
3. 检查同步 checkpoint 与业务数据一致，必要时使用安全回看窗口重放。
4. 定期演练凭证撤销、密钥轮换和数据库恢复。
5. 生产 RPO/RTO 与保留天数由用户决策，参见 NFR。

## 故障 runbook（草案）

| 症状 | 排查 | 处理原则 |
|---|---|---|
| 401/403 | 授权是否失效/角色不符 | 暂停同步，提示管理员重新授权，不重试风暴 |
| 429 | 查看操作限额和任务并发 | 降速退避，配额保护 |
| 多页同步中断 | 查 checkpoint、已提交页 | 幂等重放，不跳过页 |
| 金额偏差 | 查币种、退款、事件分类、成本版本 | 出具差异明细，不直接覆盖原事件 |
| FBA 数量异常 | 查站点/sku/快照时间与字段语义 | 保留历史观测，禁止将未知当作零 |
| DB 不可用 | 网络、空间、连接池、备份 | 恢复后安全重放任务 |

## 发布前门禁

完成安全认证、备份恢复、数据库迁移、日志脱敏、跨租户测试和可观测性后才能讨论生产部署。
