# INPUT-001 · 项目负责人需提供的资料与决策

> **无需上传 Amazon 密钥、Token、买家资料或真实订单。** 下列优先项回答后即可更新 PRD/ERD。标为「默认」的是临时设计假设，不是事实。

正式决策登记见 [DEC-001](../governance/decision-register.md)。优先回答 Q01/Q02/Q04/Q05/Q06/Q10：这将决定首发接入范围与财务和数据模型是否可冻结。没有真实样本时可以先提供假设，仍须标注「未验证」。

## 第三轮优先答复方式（可只选 A/B 或补充自定义）

请先看 [G1 审查包](../product/g1-review-package.md) 与 [决策选项表](../governance/decision-register.md)。优先答复 **DEC-01、02、03、05、06、07、08、15**。无需一次性给 18 个问题全部答案；未答仍标 TBD，**不会阻止写其他设计文档，但会阻止 G1 正式冻结**。

建议只提供以下非敏感信息：首发 US 是否合适；FBA/FBM 是否按“FBA 全部只读 + FBM 订单只读”；内部 SKU 现有码规则；你是否认可虚构订单 `40-2-6-4-13=15 USD` 标为“预估订单贡献额”；是否希望第一版跨币种折算。**不用提供真实 Seller ID、Token、订单地址、客户姓名或账户截图。**

## A. 必须先确认（阻塞 G1）

| 编号 | 需要提供什么 | 临时默认 | 对设计的影响 |
|---|---|---|---|
| Q01 | 目标用户：仅自己使用还是允许其他卖家私有部署？ | 开源自托管，首个试点为私有卖家 | 授权方式、安全责任和安装流程 |
| Q02 | 首发站点/区域：US、CA、UK、DE、JP 等？ | US 优先 | Marketplace 映射、货币、时区、接口区域 |
| Q03 | 店铺数量与大致日订单量区间 | 1–10 账户，小团队 | 同步/分页/任务限流与容量 |
| Q04 | 首发 FBA、FBM 或二者？ | FBA 优先，FBM 订单可只读 | 库存与履约口径 |
| Q05 | 主要利润需求：订单毛利、SKU 毛利、含广告经营利润？ | 订单/ SKU **预估毛利** | 费用、汇率与成本模型 |
| Q06 | SKU 与产品编码是否现有标准？ | 内部 SKU 唯一，允许映射 | 数据迁移、SKU 关系 |
| Q07 | 开源协议是否确定 Apache 2.0？ | 暂按 Apache 2.0 评审 | 贡献治理与发布 |
| Q08 | 语言：中文优先还是中英双语同时完成？ | UI 中文优先，文档双语入口 | i18n / 贡献要求 |

## B. G2 前需决定

| 编号 | 需要提供什么 |
|---|---|
| Q09 | 运维方式（本地 NAS、云服务器、K8s）、预算及备份期望 |
| Q10 | 是否实际拥有可用的 Amazon SP-API developer/应用权限（只要状态，不要凭证） |
| Q11 | 是否需要跨租户 SaaS；还是一个企业多个店铺的组织隔离 |
| Q12 | 业务角色与审批：管理员、运营、财务、只读，是否存在采购审批 |
| Q13 | 商品成本来源：人工、Excel、采购单、ERP 原有系统；更新频次 |
| Q14 | 汇率来源与折算币种；每月汇率、交易日汇率或结算日汇率 |
| Q15 | 对账口径：订单发生制、平台入账制或银行结算制；是否需要三套视图 |

| Q17 | 是否需要历史数据回填，回填多久；可接受的同步延迟 |
| Q18 | 数据保存/删除政策及隐私需求；是否限制 PII 零落盘 |

## C. 可选材料（只用脱敏示例）

- 一份虚构/脱敏的商品 SKU 与 Seller SKU 映射示例（5–10 行）。
- 自定义商品成本模板（列名即可，不用真实采购价格）。
- 想看的 dashboard 指标清单与现有报表截图（先移除账号与订单 PII）。
- 对「利润」的手算示例：一笔模拟订单 + 已知费用 + 期望最终展示。
- 目标站点列表、预期部署系统与贡献者技术偏好。

## D. 决策登记

每项决策在 GitHub Issue/ADR 中记录：决定、备选项、影响文档、负责人、日期、状态。未确认的问题保持 TBD，不假造业务口径。详见 [文档控制](../governance/document-control.md)。
