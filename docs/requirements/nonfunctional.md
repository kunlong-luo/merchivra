# NFR-001 · 非功能需求与服务级目标

> 数值均为 **设计建议目标**，非已测性能承诺。启动前确认目标数据量和部署环境。

| ID | 类别 | 建议目标 / 验收办法 |
|---|---|---|
| NFR-SEC-01 | 租户隔离 | API、查询、后台任务均默认拒绝跨租户访问；自动化负例必须通过 |
| NFR-SEC-02 | 凭证保护 | Refresh Token/密钥不写入 Git/日志，存储加密，运行时最小访问权限 |
| NFR-SEC-03 | 默认安全 | 登录认证完成前不对公网开放；管理员最小权限和敏感操作审计 |
| NFR-DATA-01 | 财务正确性 | 精确十进制计算，金额原始币种不丢失，费用事件重放不重复记账 |
| NFR-DATA-02 | 可审计 | 关键字段带 source、sourceId、sourceTime、ingestedAt、mappingVersion |
| NFR-SYNC-01 | 同步可靠 | 可恢复游标、幂等 upsert，429 等瞬时故障退避重试并记录耗尽原因 |
| NFR-SYNC-02 | 反压 | 同卖家/站点/接口的并发由配额限流约束，不假设固定额度 |
| NFR-PERF-01 | 查询性能 | 参考环境、10 万订单行时常用列表 p95 < 2 秒（不含外部 API），以压测确认 |
| NFR-PERF-02 | 交互性能 | 典型页面首屏可交互目标 < 3 秒（约束设备/网络后测试） |
| NFR-OPS-01 | 恢复 | 备份与恢复流程可演练；建议目标 RPO 24h / RTO 4h，待业务确认 |
| NFR-OPS-02 | 可观测 | 日志含 requestId/jobId，指标含同步延迟、失败率、任务耗时、重试数 |
| NFR-REL-01 | 兼容 | API 版本及数据库迁移有升级说明；版本破坏性变化须发布迁移指南 |
| NFR-TEST-01 | 测试 | domain / adapter / API / migrations / tenant isolation 的自动化测试列为发布门槛 |
| NFR-UX-01 | 国际化 | MVP 中文/英文文案可扩展；日期和金额与租户/站点时区、币种一致 |
| NFR-LIC-01 | 开源 | 可读文档、开源许可证、无生产凭证的 Mock 演示、离线启动说明 |

## 容量假设（待确认）

参考小团队初版：1–10 个 Seller 账户、数十个 Marketplace、数十万订单行/年；不据此承诺 Amazon API 拉取速度。实际容量、并发任务数、长期归档周期在压测前决定。

## 环境基线（仅设计）

开发：Java 21 / Spring Boot + Vue 3 / PostgreSQL / Redis / Docker Compose。生产建议以 TLS 反向代理、外部密钥管理、受限数据库网络、备份与指标平台包围服务；具体实例规格待压测。
