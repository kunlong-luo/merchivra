# ADR-0001 · 初期采用模块化单体

- **状态：Proposed**
- 日期：2026-10-30
- 决策：后端先采用 Java 21 + Spring Boot 模块化单体，异步任务按逻辑隔离；不预先拆成多个独立部署微服务。

## 背景
MVP 业务涉及订单、库存、成本、财务关联交易，团队和真实负载尚不确定。微服务会立即引入分布式事务、消息可靠投递、配置、追踪和运维成本。

## 决策理由
便于本地 Docker 启动、跨业务实体事务、贡献者理解和测试。通过端口与适配器划分领域；避免 ORM/数据库访问跨模块偷穿边界。

## 备选方案
微服务：强隔离但运维成本高；纯单体无模块边界：上手简单但演化困难。

## 影响与复审触发
今后出现明确扩容/发布节奏需求时评估拆分 Worker 或独立服务。先证据后拆分。开发评审需检查模块依赖图。
