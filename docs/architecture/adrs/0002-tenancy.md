# ADR-0002 · 单库共享 Schema + 租户显式隔离

- **状态：Proposed**
- 日期：2026-10-30
- 决策：初版 PostgreSQL 同库共享 Schema；每个业务实体显式 `tenant_id`，服务层强制租户上下文，数据库查询/唯一键二次约束。

## 背景
项目开源自托管，第一批用户可能只有单组织，但日后可能有多个独立店铺组织。需要预留隔离而不引入每租户数据库的高运维成本。

## 规则
1. tenantId 来自经过验证的服务端会话/任务上下文，不接受用户上传作为授权依据。
2. 所有查询和批量任务必须带租户过滤。合适的表评估 PostgreSQL RLS 作为第三道防线，但不能依赖 RLS 替代应用权限。
3. 唯一键包含租户及平台账户作用域；跨租户测试不可缺失。
4. 令牌、导出数据、缓存 key、对象存储路径同样必须租户隔离。

## 备选
每租户独立数据库：隔离更强、迁移与运维复杂；单租户专用模式：轻量但后续重构成本高。

## 复审触发
出现大型 SaaS 和不同数据驻留/隔离要求时，重新决定共享 Schema、RLS 与单独数据库方案。
