# FIN-001 · 金额、成本、利润与对账口径

**状态：业务口径待卖家/财务负责人确认。** 本文是可实现的草案，不构成会计或税务建议。

## 必须区分的三张视图

1. **订单经营视图**：按订单/行的销售发生时间估算经营收益，可能尚未发生最终费用。
2. **平台财务交易视图**：按财务事件发生/入账时间记录销售收入、费用、赔偿、退款及其他调整。
3. **结算视图**：平台结算批次/可用资金/回款，不等同销售额；与财务事件核对。

## 金额来源优先级与防重复核算

**预计销售额**主要使用 Orders 的业务金额；**已入账金额**使用 Finances 事件归类；**结算金额**使用已证实的支付/结算关联，三者为不同视图，不能直接加总。

- 当相同订单在 Orders 和 Finances 都出现时，不能把两条来源当作两个收入事实。
- 财务交易的「净额」不能未经拆解又当作「收入」并二次减去已内含的费用。来源中如果没有可证明的明细，仅显示未分类/待核对。
- 不具可靠唯一键的事件先隔离核实，不强行按金额/时间合并，以免丢失真实相同金额的交易。
- 成本、折扣、退款和税金的发生制/入账制选择属于 G1 决策，不允许 UI 偷换时间轴。
- 对缺失广告、仓储、头程、税费等明确标示未覆盖，不能称为净利润。

完整来源、匹配及数据完整度规则见 [DATA-002](source-reconciliation.md)，角色/业务闭环见 [DOM-001](domain-state-model.md)。

## 估算模型 v0.1

`预估贡献毛利 = 订单商品收入 + 可归属运费收入 - 退款和折扣 - 已知平台交易费用 - 商品成本 - 已知履约费用`

- 可归属税金、汇率损益、广告、仓储、头程、固定支出等，分别列为「已计入 / 未计入 / 待分类」。
- 把「未取得数据」标记为 `UNKNOWN` / `INCOMPLETE`，**不能按 0 处理**。
- 商品成本 = 对应期间有效单位成本 × 数量；多币种换算需指定汇率日期与来源。
- 费用若发生在订单之外，通过可审计的分配规则关联 SKU 或留在「未分配费用」。
- 计算输出保存 `calculation_version`、`cost_version`、`fx_rate_id`、`source_event_ids` 和 `completeness_status`。

## 示例（虚构美元订单）

| 项目 | 金额 USD | 说明 |
|---|---:|---|
| 商品收入 | 40.00 | 不含代收代缴税金的示意口径 |
| 退款/折扣 | -2.00 | 已知且可归属 |
| 平台交易费用 | -6.00 | 已知 |
| 履约费用 | -4.00 | 已知 |
| 商品成本 | -13.00 | 有效成本版本 |
| **预估贡献毛利** | **15.00** | *不含广告、仓储、头程、固定费用、税务等* |

如广告费用未知，应展示「15.00 USD（部分费用未计）」而不是「净利润 15.00 USD」。

## 事件对账流程

```mermaid
sequenceDiagram
participant ORD as Orders
participant FIN as Finances
participant COST as Cost history
participant CALC as Margin projection
participant UI as Report UI
ORD->>CALC: 标准化订单金额/时间
FIN->>CALC: 财务事件/退款/费用
COST->>CALC: 按生效期取成本
CALC->>CALC: 校验币种/唯一键/费用覆盖
CALC-->>UI: 估算金额 + 完整度 + 计算版本
UI->>CALC: 查看来源和差异
```
