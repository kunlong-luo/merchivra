# TEST-002 · 端到端业务场景与样本矩阵

**此文件是设计阶段的测试规格，不是已执行报告。** 所有数据是纯虚构，且必须与 AC/FR 的真实实现相对应。

## 场景 E2E-01：首次启动和授权拒绝
**输入**：新安装实例，没有用户、没有 Amazon 凭证；一次性引导令牌 `bootstrap_mock_1` 仅供测试。  
**步骤**：初始化租户 → 创建 Owner → 再次访问初始化入口 → 以未授权用户请求私有订单。  
**预期**：首次成功、第二次引导拒绝、私有 API 返回 401/403、没有默认口令或密钥回显。  
**追踪**：FR-SYS-01/02、IAM-001、AC-01/16/27。

## 场景 E2E-02：两个租户相同 Seller SKU
**输入**：Tenant A 与 B 都有 Seller SKU `RED-MUG`，但商品和账户完全不同。  
**步骤**：各自导入 Listing → 从 A 搜索 B 的订单 ID → 编辑 A 的 SKU 映射。  
**预期**：跨租户无法读取；B 数据未变；映射冲突不会泄漏资源存在性。  
**追踪**：FR-CAT-02、IAM-001、DATA-001、AC-03/19。

## 场景 E2E-03：乱序订单与部分退款
**输入**：订单 `MOCK-001` 40.00 USD，`SHIPPED`；先收到 2.00 USD 退款，再获取旧订单通知 `UNSHIPPED`。  
**步骤**：导入已发货订单 → 导入退款 → 导入较旧状态 → 重跑同步。  
**预期**：履约仍为 SHIPPED、退款 PARTIAL；不会产生重复订单/退款；显示原始状态时间及关联来源。  
**追踪**：FR-ORD-01/03、DOM-001、AC-06/18/20。

## 场景 E2E-04：未映射 SKU 与库存观测
**输入**：Seller SKU `ORPHAN-01` 无内部 SKU，FBA 第 1 次可售 12，第 2 次 9，第 3 次返回缺失 fulfillable 值。  
**预期**：三次事实保留；当前观测显示 UNKNOWN 或适当时效标记，不因为缺失当 0；原始 SKU 后续可映射。  
**追踪**：FR-CAT-02/INV-01、DATA-001、DOM-001、AC-07/19/21。

## 场景 E2E-05：Orders + Finances 不重复入账
**输入**：Orders 预计收入 40 USD；Finances 相关交易收入 38 USD（其中 2 USD 退款已计入）；商品成本 13 USD，其他费用数据部分缺失。  
**预期**：预计收入与入账收入分别展示，不合计为 78；缺失费用使利润状态为 PARTIAL；无法确定的财务行保留未分配。  
**追踪**：FR-FIN-01/02、DATA-002、FIN-001、AC-11/22/24。

## 场景 E2E-06：持久 Stream 与 Token 过期
**输入**：3 页订单，第二页后 Worker 崩溃；恢复时平台分页 Token 已过 24h；并发另一个 Worker。  
**预期**：用 checkpoint 时间窗重扫；重复 upsert 无重复；单有效租约；旧 Worker 无法提交过期 lease。  
**追踪**：FR-SYNC-01/02、SYNC-002、AC-05/12/13/23/25。

## 场景 E2E-07：金额与时间口径
**输入**：同一内部 SKU 在 US 40 USD、EU 20 EUR，两笔成本处于不同生效版本。  
**预期**：原币独立；没选汇率和日期不能生成无标识单一汇总；重算可追溯成本版本；视图明确 order time / posted time 的时间轴。  
**追踪**：FR-COST-01/FIN-02、FIN-001、AC-09/14。

## 场景 E2E-08：API 契约错误态
**输入**：未认证访问、资源跨租户、重复触发同步、Amazon 授权被撤销、异步 Worker 遇到 429。  
**预期**：401/404/409 与合适的连接状态；API 仅返回脱敏的 requestId 和错误码，Worker 退避逻辑与 UI 任务状态对齐，不泄漏 Token。  
**追踪**：API-001、SEC-001、AC-01/12/16/26/27。

## 测试数据最低集合

2 tenants × 至少 2 accounts × 至少 3 marketplaces；多币种、同 ASIN 异 SKU、缺失映射、时间乱序、退款、库存快照过期、财务未知来源、重复事件、API 429/401/5xx 与分页过期。
