# V180 — 利润来源可追溯与跨版本安全比较

状态：**PR 开发分支，必须通过合并前 Chromium + Next16/React19/Java25 与精确主线 SHA 的 A3 才可归档为合成验收。**

## 核心目标

不再把界面美化当作财务能力完成。Merchivra 的优先级仍是 V162 全成本与 V64 期间利润，所有来源均应能够回溯到原始费用/账单/订单/批次证据。这里实现**可审计展示与快照安全对照**，没有制造新的外部可信来源、真实平台账单或银行结算。

### 已实现代码

1. **V64 两版已冻结任务的原币比较**：从现有、受会话站点权限保护的 GET profit-reports 读取本次报告与指定历史报告，绝不调用写入 API。相同任务、任务未完成、币种/币种汇总不一致、UTC 报告期间不同，或候选/合格/阻断订单数量不同，全部明确阻断差额计算。符合条件时，按有符号销售、Amazon/FBA 费用、暂定历史商品成本与贡献合计展示**冻结快照的算术差额**。采用 BigInt 十进制定点运算，不经浮点数、不换汇。即使候选数量相同也不代表订单 ID 集合和外部费用相同，所以不能称为同比利润增长、可比经营改善或已验证净利润。
2. **逐单 BLOCKED 来源分布**：按当前已加载的候选订单页逐项汇总阻断原始 readiness，显示本页已处理/待处理/阻断数量；绝不把本页的 100 条以内记录冒充最多 5,000 条候选的整期统计。翻页后自然刷新统计。保留原始代码供追溯，不捏造完成原因。
3. **八类成本费用来源—账单行风险审计**：在现有 V162 成本准备度表的当前页打开 Base UI 只读证据抽屉，展示本地来源 UUID、申报原币、独立元数据复核、分摊状态、已批准但未认证金额、关联参考账单行数量、与其他来源共用数量及审批阻断。共用参考行是重复归属风险，**不等于证明重复扣费**；本地参考行也不构成 Amazon/银行原始账单认证，不允许进入最终净利润。
4. **来源/会话隔离**：版本查询始终使用当前会话已选 marketplaceId 和已经得到的任务 ID；切换租户/市场/报表清空对比与抽屉状态；所有只读审计明细仅来自当前页面已得到的服务端分页。本轮没有新增后端权限、OAuth、数据库、费用公式和对外 API。
5. **不重复造轮子**：现有 Next.js 16.4.5 + React19、Base UI、TanStack Query、Vite 受控回退、已有 CSS 设计系统。

## 测试

- Vitest 使用不同日期、币种、未完成、候选量不一致和相同任务测试差额阻断；以超过 IEEE-754 精确整数范围的原币数字、负数及小数测试 BigInt 差分；BLOCKED 原因以本页逐条汇总。
- CI 专属 Chromium Vite/Next16 合成夹具内填入两版完成的 V64 报表与一笔人工费用记录。浏览器实际选择历史版本，核实 +1.1 原币差额，检查本页缺成本代码，打开人工费用来源抽屉并验证“不得入账”提示；不得联系 Amazon 或读取任何真实租户数据。
- 完整 PG18 + Java25 + Spring Session/CSRF + React/Next16 + Chrome + Compose HTTP 继续在合并后精确主线 SHA A3 执行，#104 必须继续 NO-GO。

## 仍未实现的 P0

当前只提供**来源关联数量**、共用风险、手工来源元数据和未认证的冻结版本合计。尚无外部真实 Seller/Ads 授权、可独立验证的平台原始账单行身份、银行净到账、WMS 真实运营主体与实体签收、退货原币 COGS 回转、全费用认证。V162/V64 真正净利润仍**不可计算**，不得因为 V180 的表格和差额而改变任何账务或发布门禁。

下一阶段优先补齐平台账单行—费用来源的可核对复合键和不可变历史证据，再接入 V162 的正式期间全成本核算；正式页面以 Next16 为主，Vite 仅受控回退，Spring Boot 4.1/Java25/Gradle/PG18 不变。
