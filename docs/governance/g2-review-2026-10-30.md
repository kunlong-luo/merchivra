# REVIEW-004 · 第四轮 G2 物理数据与接口架构评审记录

**日期：2026-10-30｜阶段：G2 候选方案编制与静态交叉评审**  
**最终结论：G2 尚未通过。** G1 仍缺正式业务签署，所有 G2 设计不得声明为可投产实施。

## 1. 本轮工作范围

- 数据：从概念 ERD 延伸至 PostgreSQL 的表/约束/索引/租户复合外键/时间版本/财务来源唯一键。
- 一致性：同步租约、事务、重放、成本历史、来源事实与衍生投影。
- API：资源、分页、日期、decimal money、错误码、安全模式的候选 OpenAPI 契约。
- 安全：跨租户/跨账号的服务端、库层、Worker 约束。
- 测试：G2-AC 故障注入和角色越权验收。

| G2-F12 | Medium | API 版本/错误结构与页面可能漂移 | 正式 OpenAPI 候选 + G2-QA 追踪 | 待手工/自动 schema 验证 |

### 操作级新增核对

- Orders 查询 Token 有 24h 有效期，且下一页需保持相同过滤范围；据此把 `filterFingerprint` 纳入 Stream 键与 page 重试协议。
- FBA `getInventorySummaries` 的 `details` 默认 false，不请求明细时库存数字的缺失不是“实际为 0”。
- 默认 usage plan 只是参考，按操作/账号/应用及响应限额进行运行时管理，避免统一固定 QPS。
- 以上结论来自官方公开参考，尚未取得真实卖家 API 调用证据。
